# Plan: Озвучка Zcode «по абзацам на лету» в Agent Voice

## Режим
Точно как Claude Code: каждый абзац ответа ассистента начинает играть, когда Zcode переходит к следующему действию, не дожидаясь конца хода. Источник текста — **SQLite Zcode** (`~/.zcode/cli/db/db.sqlite`), читаемый встроенным `node:sqlite` (проверено на Node v26.4.0 рантайма).

## Что подтвердил сверкой с официальной докой (https://zcode.z.ai/en/docs/hooks)

✅ **События и конфиг** — подтверждены: 7 событий, `hooks.enabled:true` обязательно для конфиг-хуков, `SessionStart`/`PreToolUse`/`Stop` существуют, `PreToolUse` matcher = имя инструмента, порядок user→workspace→plugin hooks.

✅ **stdin содержит `session_id`** — основной формат payload:
```json
{ "session_id":"...", "transcript_path":"/tmp/zcode-hook/...", "cwd":"...",
  "permission_mode":"default", "hook_event_name":"PreToolUse",
  "tool_name":"Write", "tool_input":{...}, "tool_use_id":"..." }
```

⚠️ **КРИТИЧЕСКОЕ ОТКРЫТИЕ — прежний дискриминатор неверен.** Zcode payload **содержит `transcript_path`** (как Claude) и `Stop` несёт `last_assistant_message`. То есть Zcode-payload **почти идентичен Claude Code** и пройдёт через существующий `parseClaudeHookPayload` (он отвергает только при наличии `turn_id`). Нельзя различать по «отсутствию transcript_path».

**Решение дискриминатора:** наш hook-скрипт сам дописывает маркер `agent:"zcode"` в payload перед записью в inbox. Codex/Claude хуки маркер не дописывают. `processZcodeEvent` проверяет первым (по маркеру), Codex/Claude проваливаются дальше. Надёжно и не зависит от формата полей.

✅ **`transcript_path` у Zcode — временный** (`/tmp/zcode-hook/...`, чистится Zcode'ом после хука). Это лишний аргумент НЕ читать его, а брать только `session_id` и читать из **SQLite** (стабильный источник, уже верифицированный: 31 ассистент-абзац в текущей сессии, корректный JOIN на `role='assistant'`).

## Подтверждённые факты (код + эмпирика)
- Текст ассистента: `part.data={"type":"text","text":"..."}`, родитель `message.data.role="assistant"`. Фильтр только по `type='text'` **нельзя** (531 user-text part) — нужен JOIN на `role='assistant'`.
- **Субагенты** (`task_type='subagent_child'`, 596 текст-parts) исключаем через `session.task_type='interactive'`.
- Watermark-ключ: `part.id` стабилен → как `sourceId`; `(time_created, sequence)` для порядка.
- `node:sqlite` `DatabaseSync`, `readOnly:true` + `json_extract` — проверены. WAL читается прозрачно. Никаких npm-зависимостей.

### Фаза 2 — backend-сервисы Zcode
- **Новый `main/services/zcode-event.ts`**: `parseZcodeHookPayload` — возвращает `null`, если `payload.agent !== "zcode"` (это и есть дискриминатор); требует `session_id` + `hook_event_name`∈{SessionStart,PreToolUse,Stop}; отвергает `stop_hook_active===true`. `zcodeBlockKey(sid, partId)` = `` `zcode:${sid}:${partId}` ``. **НЕ требует `transcript_path`** (читаем из SQLite).
- **Новый `main/services/zcode-transcript.ts`**: `readZcodeSpeechBlocks(dbPath, sessionId): Promise<SpeechBlock[]>`. Открывает `new DatabaseSync(dbPath, { readOnly: true })` из `node:sqlite`; при ошибке → `[]`; `db.close()` в `finally`. Путь по умолчанию `~/.zcode/cli/db/db.sqlite` (env `ZCODE_DB_PATH`). Запрос:
  ```sql
  SELECT p.id AS pid, json_extract(p.data,'$.text') AS text
  FROM part p JOIN message m ON m.id = p.message_id
  WHERE p.session_id=?
    AND json_extract(m.data,'$.role')='assistant'
    AND json_extract(p.data,'$.type')='text'
    AND EXISTS (SELECT 1 FROM session s WHERE s.id=p.session_id AND s.task_type='interactive')
  ORDER BY p.time_created ASC, p.sequence ASC
  ```

## Ключевое отличие от первого варианта плана
**Дискриминатор источника** изменён: вместо «отсутствия `transcript_path`» (что неверно — Zcode его содержит) используется **маркер `agent:"zcode"`, дописываемый нашим hook-скриптом**. Zcode проверяется первым в `processEventFile`. Источник данных — по-прежнему SQLite по `session_id` (временный `transcript_path` Zcode игнорируем намеренно: он чистится после хука, а SQLite стабилен).

## Нюансы
- **Гонка хук vs коммит part в SQLite:** если текст ещё не в БД при хуке — следующий хук (след. PreToolUse/Stop) подберёт; watermark сходится, только задержка.
- **Снимок конфига на старте сессии:** по доке Zcode, hook-конфиг снимается в момент старта сессии — изменения требуют **новой сессии**. Учитываем при тестировании.
- **PR через gh:** если `origin` не GitHub — дам инструкцию вручную.
